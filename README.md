## 你的工厂到底需要多大内存？三套口径别混着用

网上关于《幸福工厂》内存的答案从 4GB 到 12GB 都有，它们说的其实不是一回事。

**口径一：官方最低线。** 2021 年 10 月 26 日的 Update 5 首次推送专用服务器时，官方给的数据是至少 4GB 内存和 10GB 存储空间。这是能启动的下限。

**口径二：实测建议。** 同一份 2021 年的搭建记录里，实际测试建议 Linux 下 6GB 以上、Windows 下 8GB 以上内存，以及更多存储，才撑得住 4 人以上同时联机或大型复杂的工厂。

**口径三：一键脚本的安装门槛。** 国内流传最广的幸福工厂一键部署脚本写的是「内存至少 12G」，低于这个数「游戏服务器会内存溢出导致无限重启」，并推荐把 swap 开到 11GB。

12GB 不是让你必须买 12GB 物理内存。脚本允许用 swap 补足，也就是硬盘模拟内存。swap 防的是服务端因内存不足被系统杀掉、然后反复重启，代价是加载存档和自动保存变慢。买 8GB 物理内存再配 3–4GB swap，比直接上 12GB 物理内存便宜得多，对 4–8 人的工厂够用。

按人数给结论：

- **2–4 人、单条主线、玩到中期**：官方 4GB 能跑，但建议直接选 **4 核 4G**（洛杉矶 60 元/月、香港 68 元/月）。幸福工厂服务端更吃单核性能，实际是一核为主、其他为辅，2 核机型在自动保存和多人同时进图时容易顶住。
- **4–8 人、多条产线并行、地图上跑火车**：**4 核 8G**。这一档是踩在「Linux 6GB+、Windows 8GB+」实测建议之上的，也是多数固定小队真正该买的档位。

## 端口与连接：买完连不上，九成出在这三个 UDP 端口

《幸福工厂》专用服务器用三个端口，全部是 **UDP**，不是 TCP。买完云服务器后，要在安全组里把这三个都放行。

| 端口 | 用途 | 能不能改 |
| --- | --- | --- |
| **15777** | 查询端口，第一次连接时输入的就是这个 | 可以自由重定向，参数 `-ServerQueryPort` |
| **15000** | 标识端口（Beacon） | 不能重定向，多实例时自动递增 |
| **7777** | 游戏端口 | 启动时用 `-Port` 改，例如 `-Port=10000`；被占用会自动递增 |

2021 年那篇流传很广的搭建教程在这块有个坑：表格里 7777 一栏写着「此端口目前无法重定向」，同一行却又给出了 `-Port=???` 重写参数，正文还说「不要将端口 7777 转发为路由器上的端口 7778」。前后矛盾。以持续维护的一键脚本文档为准：7777 可以用 `-Port` 改，15777 可自由重定向，15000 不能。

端口全放行了还是连不上，有两种真实情况：

一是网络侧的限制。一键脚本的项目页上挂着一条用户反馈原文：「华为云部署后连接服务器一直超时，端口已经放开，和客服反馈后仍未解决！」端口规则只是其中一环，机房线路、安全组层级、系统自带防火墙都可能拦。

二是系统镜像不纯净。同一份文档的提示是：部署完成后服务运行正常、但连不上游戏，可以考虑 DD 系统镜像重装。国内一些商家提供的默认镜像预装了额外的安全组件或改了网络配置，服务端进程活着，UDP 包却进不来。

这两条决定了「自建」和「租面板服」的分界线：面板服卖的是「已经通了」这件事，自建买的是「我自己能改」。如果你的时间比 30 元差价贵，就别从裸机开始。

## 自己搭 vs 租面板：把工作量摊开看

自建一套 Linux 幸福工厂服务端，实际要做这些事：

1. 装 32 位运行库。Ubuntu 是 `lib32gcc1 libcurl4-gnutls-dev:i386 lib32stdc++6 lib32z1`，CentOS 7/8 是 `glibc.i686 libstdc++.i686 libcurl.i686 screen`。
2. 建一个非 root 用户 `steam`。root 账户跑不了这个服务。
3. 下载 SteamCMD，匿名登录拉服务端：
   `./steamcmd.sh +login anonymous +force_install_dir ~/SatisfactoryDedicatedServer +app_update 1690800 validate +quit`
   1690800 是《幸福工厂》在 Steam 的 App ID。
4. 如果报 `Failed to init SDL priority manager: SDL not found`，补装 `libsdl2-2.0-0:i386`（Ubuntu）或 `SDL2.i686 SDL2.x86_64`（CentOS）。
5. 把本地存档传到 `~/.config/Epic/FactoryGame/Saved/SaveGames/server`。
6. 写 systemd unit，把服务托管起来，`Restart=always`、`RestartSec=10`、`User=steam`。
7. 加一条 crontab：`0 4 * * * systemctl restart satisfactory.service`，每晚 4 点重启一次，重启时会通过 SteamCMD 自动校验更新。

系统方面，实测通过的发行版有 CentOS 7.9、CentOS 8、Debian 9/10、Ubuntu 18.04/20.04。CentOS 已经停止维护，优先选 Debian 或 Ubuntu 全系。

硬件上有一条硬限制：只支持 x86/64 架构的 AMD 或 Intel 处理器，**不支持 ARM**。看到便宜的 ARM 机型别买。

P2P 的限制也很实在：会话必须由拥有该存档的人发起；可以设「私密」或「仅限好友」，会话 ID 分享出去后非好友也能进，但每次重新启动会话 ID 都会重置，等于每次都要重发一遍；房主不在线，谁也进不去。自建还多一层不确定性——能不能在家用宽带上做端口转发，取决于你的运营商。

结论很简单：有闲置的 Linux 机器、愿意折腾一次、以后不换人，自建最省钱。只是想在周五晚上和朋友直接开工，租。

## 存档与初始化：服务器不会自己开局

专用服务器装好、启动之后是空的。它不会自动创建任何游戏，必须有人在游戏里操作：

第一个连上服务器的玩家完成初始化，包括设置服务器名称和管理密码。默认不启用玩家密码，需要的话可以在服务器管理器 UI 里补设。之后管理员才能通过管理密码进服务器设置页。

连接方式是在 Server Manager 界面点 Add Server，输入服务器 IP，端口默认 15777。

加载已有存档靠的是 **Session Name**，不是存档文件名。在游戏里查到这个存档的 Session Name，填进 Server Settings 页面，系统会自动加载对应存档。这一点卡住过不少人——直接把 `.sav` 文件名填进去是不生效的。如果是在服务器里用 Create Game 新建存档，就不用填。

存档文件的位置：

- Linux 服务器：`/home/steam/.config/Epic/FactoryGame/Saved/SaveGames/server`
- Windows 服务器：`%LOCALAPPDATA%\FactoryGame\Saved\SaveGames\server`
- 本地游戏目录：`%LOCALAPPDATA%\FactoryGame\Saved\SaveGames`

换服务器搬家，就是把 `server` 目录下的 `.sav` 拷过去，再用 Session Name 加载，产线和建筑都在。

人数上限不在游戏里改，要编辑 `Game.ini`：


[/Script/Engine.GameSession]
MaxPlayers=8


路径是 `/home/steam/FactoryGame/Saved/Config/LinuxServer/Game.ini`。改完重启服务生效。

服务端更新不需要重装，重启服务会自动通过 SteamCMD 校验并拉取新版本，一键脚本本身已经内置了每晚 4 点的重启更新。

## 常见问题

**4GB 内存够几个人玩？**
官方最低线是 4GB，实测建议 4 人以上或大型工厂用 Linux 6GB+、Windows 8GB+。2–3 人玩到中期，4GB 能跑；4 人以上同时在线建议 8GB。

**端口都放行了，为什么还是连接超时？**
三个端口必须是 UDP，不是 TCP。确认 15777、15000、7777 全部放行后仍超时，考虑机房线路问题或系统镜像不纯净，可以换镜像重装。

**专用服务器需要一直开着吗？**
需要。工厂的生产、玩家的进度都在服务端持续运行，关机期间谁也进不去。这也是租服务器相对于「房主开 P2P」的主要价值。开服频率很低的话，雨云游戏云 VPS 的动态计费（CPU 使用率低于 20% 不产生费用）比包月省。

**换服务器，存档怎么迁？**
停服，把 `SaveGames/server` 下的 `.sav` 拷到新服务器同一路径，进游戏用 Session Name 加载。不要用文件名去填。

**ARM 机器能开幸福工厂服吗？**
不能。服务端只支持 x86/64 架构的 AMD 或 Intel 处理器。

**服务器怎么更新？**
重启服务即可，启动脚本会执行 `+app_update 1690800 validate` 完成校验更新。手动更新就是重跑一遍 SteamCMD 命令。
